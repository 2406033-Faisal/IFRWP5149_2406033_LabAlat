
# Checklist Pemeriksaan Diagram Use Case
Gunakan checklist berikut untuk kedua kasus sebelum mengunggah ke LMS.

## 1. Konsistensi Elemen Pertemuan 3
- [ ] Seluruh elemen Pertemuan 3 tetap ada dan tidak berubah nama: LAB-UC01 sampai LAB-UC07, aktor Kepala Laboratorium, relasi `<<include>>` LAB-UC03 ke LAB-UC04, dan relasi `<<extend>>` LAB-UC05 ke LAB-UC03 beserta *condition* dan *extension point*-nya. ✅

## 2. Relasi Kepala Laboratorium
- [ ] Kepala Laboratorium hanya terhubung dengan satu use case, yaitu LAB-UC07 Lihat Laporan Peminjaman. ✅
- [ ] LAB-UC07 tidak mempunyai relasi lain, seperti `<<include>>`, `<<extend>>`, *generalization*, atau *realization*. ✅
- [ ] Tidak ada aktor lain yang terhubung ke LAB-UC07.  ✅

## 3. Asosiasi Aktor
- [ ] Asosiasi ke LAB-UC01 dan LAB-UC03 digambar satu kali dari aktor Peminjam. ✅
- [ ] Asosiasi khusus Mahasiswa ke LAB-UC05 tetap digambar langsung dari Mahasiswa. ✅

## 4. Generalization Aktor
- [ ] Setiap aktor khusus terhubung dengan satu panah *generalization* ke aktor umumnya. ✅
- [ ] Segitiga kosong menunjuk ke aktor umum. ✅
- [ ] Tidak ada asosiasi warisan yang digambar ulang dari aktor khusus. ✅

## 5. Generalization Use Case
- [ ] Setiap use case khusus terhubung dengan satu panah *generalization* ke use case umumnya. ✅
- [ ] Segitiga kosong menunjuk ke use case umum. ✅

## 6. Collaboration dan Realization
- [ ] *Collaboration* digambar sebagai elips bergaris putus-putus. ✅
- [ ] Nama *collaboration* sama persis dengan use case yang direalisasikan. ✅
- [ ] *Collaboration* tidak terhubung langsung ke aktor. ✅
- [ ] Relasi *realization* digambar dari *collaboration* menuju use case menggunakan garis putus-putus berujung segitiga kosong. ✅

## 7. Relasi Include 
- [ ] Relasi `<<include>>` pada pencatatan pengembalian atau tugas mengarah ke perilaku yang disertakan. ✅

## 8. Batas Sistem
- [ ] Aktor berada di luar batas sistem. ✅
- [ ] Use case dan *collaboration* berada di dalam batas sistem. ✅

## 9. Konsistensi Nama dan ID
- [ ] Nama dan ID pada diagram, katalog, serta deskripsi sama persis. ✅

## 10. Keterlacakan Kebutuhan
- [ ] Setiap elemen baru tertelusur ke LAB-R07 sampai LAB-R11 untuk kasus LAB atau SIA-R07 sampai SIA-R12 untuk tugas SIA. ✅

## 11. Keutuhan Berkas Pertemuan 3
- [ ] Kebutuhan Pertemuan 3 tidak diubah artinya. ✅
- [ ] Berkas P03 tidak ditimpa. ✅

## 12. Pemeriksaan Berkas dan Versi
- [ ] Berkas sumber dapat dibuka kembali dan disunting. ✅
- [ ] Hasil ekspor sesuai dengan berkas sumber terkini. ✅
- [ ] Nomor versi berkas sumber dan hasil ekspor sama.  ✅

## 13. Pertanyaan Terbuka
- [ ] Kebutuhan yang belum dimodelkan, misalnya keterlambatan dan denda pada kasus LAB, ditandai sebagai pertanyaan terbuka dan tidak dianggap selesai. ✅
